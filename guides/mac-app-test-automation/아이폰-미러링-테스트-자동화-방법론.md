# Mac에서 아이폰 앱 테스트하기 — iPhone 미러링 + Computer Use

> 목표: 아이폰 화면을 Mac에 연결하고, AI가 화면을 읽고 한 번씩 조작해 테스트 결과를 기록한다.
> 문서 기준일: 2026-10-04.

iPhone 미러링 창을 Computer Use로 읽고 조작하는 방식이다. 기본 조작이 가능한 경로이며, 새 환경에서는 아래 통과 기준으로 재현한다. 화면을 보고 판단하는 점검과 대량·반복 회귀 테스트의 안정성 검증은 별도다.

## 1. 준비물과 연결 조건

Apple의 [iPhone 미러링 공식 안내](https://support.apple.com/en-us/120421)에 따라 확인한다.

| 항목 | 조건 |
| --- | --- |
| Mac | Apple Silicon 또는 T2 보안 칩, macOS Sequoia 15 이상 |
| iPhone | iOS 18 이상, 암호 설정 |
| 계정 | 두 기기에 같은 Apple 계정으로 로그인, 이중 인증 사용 |
| 연결 | Wi-Fi·Bluetooth 켜짐, 기기가 가까이 있음 |
| iPhone 상태 | 미러링 사용하는 동안 잠금 상태 |
| Mac 상태 | 인터넷 공유·AirPlay·Sidecar 동시 사용 조건 확인 |
| 제공 지역 | Apple 공식 안내의 지역 제한 확인 |

Computer Use 자체 준비는 [활성화 가이드북](computer-use-guide.md)을 따른다. Claude Code 사용자는 [플러그인 가이드](claude-code-computer-use-guide.md)를 추가로 따른다.

## 2. 먼저 사람이 미러링을 연결한다

1. Mac의 응용 프로그램 또는 Spotlight에서 `iPhone 미러링`을 연다.
2. 안내에 따라 Mac 인증을 직접 수행한다. 아이폰 암호 확인이 필요하면 아이폰에서 처리한다.
3. 알림 허용 여부를 선택하고 아이폰을 다시 잠근다.
4. Mac 창에 아이폰 홈 화면이 보이는지 확인한다.
5. 마우스로 테스트 앱을 열어 연결 상태를 확인한다.

**통과 기준:** Mac에서 실제 아이폰 화면이 보이고 의도한 앱을 열 수 있다. 연결 오류는 Computer Use 설정 전에 해결한다. 아이폰을 직접 잠금 해제하면 미러링이 중단될 수 있다. [연결·사용 방법](https://support.apple.com/en-us/120421)

## 3. AI의 첫 조작을 검증한다

Computer Use 계산기 검증을 마친 세션에 아래 요청을 전달한다.

```text
Computer Use로 Mac의 iPhone 미러링 앱을 찾아 현재 화면을 읽어줘.
앱 이름이 다르면 실제 앱 목록의 이름·식별자를 확인해.
[테스트 앱]을 열고 현재 화면을 다시 확인해.
[되돌릴 수 있는 버튼]을 한 번 누른 뒤 새 화면을 읽어줘.
[기대 결과]와 실제 화면을 대조해 PASS / FAIL / BLOCKED로 보고해.
연결·암호·권한 인증은 필요한 사용자 조작을 안내하고 기다려줘.
```

| 단계 | 통과 기준 |
| --- | --- |
| 상태 읽기 | 미러링 창 내용이 실제로 보임 |
| 한 번 조작 | 지정한 앱·버튼이 눌림 |
| 결과 재확인 | 새 화면에서 기대한 변화 확인 |
| 기록 | 기대 결과·실제 결과·환경·증거 경로 저장 |

검은 화면이나 입력 실패는 성공으로 처리하지 않는다. 사람도 조작이 안 되면 미러링 연결부터, 사람은 되는데 AI는 안 되면 Computer Use의 권한·도구 연결부터 확인한다.

## 4. 테스트를 진행한다

1. 대상 앱·시나리오·입력값·초기 상태·중단 지점을 정한다.
2. 화면 읽기 → 한 번 조작 → 새 화면 확인을 반복한다.
3. 기대 결과와 실제 결과를 비교한다. 화면 도달만으로 PASS를 선언하지 않는다.
4. 개인정보를 제외한 증거를 결과 문서 옆에 저장한다.
5. 다음 실행을 위해 초기 상태로 복원할 방법을 기록한다.

검색 → 결과 목록 → 상세 정보처럼 조회 중심 흐름부터 시작한다. 운영 계정의 결제·발송·승인은 테스트 범위에 별도 명시하지 않았다면 진행하지 않는다.

## 5. 한계와 다른 경로

- 아이폰이 잠겨 있어야 연결된다. 기기를 직접 사용할 때는 테스트를 중단한다.
- 알림은 Mac에서 받을 수 있다. 카메라·마이크와 생체 인증 등 제약은 [Apple 공식 안내](https://support.apple.com/en-us/120421)의 최신 내용과 실제 화면을 대조한다.
- 마우스·키보드 기반이다. 멀티터치·센서·실물 카메라 동작은 별도 기기 테스트를 계획한다.
- AI의 화면 판독은 숫자 오독·누락이 생길 수 있다. 중요한 값은 증거와 재대조한다.
- 반복 회귀·내부 상태 단언이 필요하면 [Appium](https://appium.io/docs/en/latest/) 또는 XCTest 계열 도구를 별도로 설계한다. 서명·빌드·기기 설정 요건은 해당 도구 문서에서 확인한다.
- ADB는 안드로이드 전용이다. 아이폰에 ADB 명령을 적용하지 않는다.

다른 환경에서 성공한 결과를 그대로 자신의 환경 완료로 간주하지 않는다. 사용한 OS·호스트·앱 버전과 각 단계 결과를 기록한다.
