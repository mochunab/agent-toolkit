# Mac에서 안드로이드 연결·미러링하기

> 목표: USB 디버깅을 허용하고 ADB 연결을 확인한 뒤 scrcpy로 화면을 띄운다.
> 문서 기준일: 2026-10-04.

ADB는 Mac에서 안드로이드에 명령을 보내는 도구다. scrcpy는 그 화면을 Mac 창에 표시하고 마우스·키보드로 조작하는 도구다. AI의 ADB 직접 테스트에는 scrcpy가 필수는 아니다.

## 1. 도구를 설치한다

Homebrew가 없다면 [설치 안내](https://brew.sh)를 먼저 따른다. 터미널에서 순서대로 실행한다.

```sh
brew install --cask android-platform-tools
brew install scrcpy
adb version
scrcpy --version
```

**통과 기준:** 두 버전 명령 정상 출력. Homebrew를 쓰지 않는 환경은 [Android Platform Tools](https://developer.android.com/tools/releases/platform-tools)와 [scrcpy macOS 설치 문서](https://github.com/Genymobile/scrcpy/blob/master/doc/macos.md)의 지원 경로를 따른다.

## 2. 폰에서 USB 디버깅을 켠다

1. 데이터 전송을 지원하는 USB 케이블을 준비한다.
2. 폰의 설정 → 휴대전화 정보에서 빌드 번호를 여러 번 눌러 개발자 옵션을 활성화한다. 제조사에 따라 메뉴 위치가 다르다.
3. 개발자 옵션에서 USB 디버깅을 켠다.
4. Mac에 연결하고 폰을 잠금 해제한다.
5. 폰의 USB 디버깅 RSA 승인 팝업을 확인하고 사용할 Mac을 허용한다.

승인은 사용자가 폰에서 수행한다. 명령 실행만으로 이 승인을 대신할 수 없다. [ADB 연결 공식 안내](https://developer.android.com/tools/adb)

## 3. 연결을 확인한다

```sh
adb devices -l
```

| 결과 | 다음 행동 |
| --- | --- |
| `device` | 대상 기기를 선택하고 진행 |
| `unauthorized` | 폰 잠금 해제·승인 팝업 확인 |
| `offline` | 연결·기기 상태 확인 후 재연결 |
| 목록 비어 있음 | 데이터 케이블·포트·USB 디버깅 확인 |

기기가 하나면 다음 명령으로 미러링한다.

```sh
scrcpy
```

여러 기기가 연결됐다면 출력의 시리얼을 로컬에서만 지정한다.

```sh
export APP_TEST_SERIAL='YOUR_DEVICE_SERIAL'
scrcpy -s "$APP_TEST_SERIAL"
```

`YOUR_DEVICE_SERIAL`은 자리표시자다. 실제 시리얼은 공유 문서에 넣지 않는다.

**통과 기준:** Mac 창에 폰 화면이 보이고 한 번 클릭한 결과가 폰에도 반영된다. 자동화는 [ADB 테스트 가이드](안드로이드-앱-테스트-자동화-가이드.md)로 이어간다.

## 4. 필요한 옵션만 추가한다

| 목적 | 명령 |
| --- | --- |
| 폰 화면 끄고 Mac에서 보기 | `scrcpy -S` |
| 충전 중 화면 켜짐 유지 | `scrcpy -w` |
| 녹화 | `scrcpy --record=test.mp4` |
| 항상 위에 표시 | `scrcpy --always-on-top` |
| 종료 | 창 닫기 또는 해당 터미널에서 Ctrl+C |

여러 기기 환경은 위 명령에도 `-s "$APP_TEST_SERIAL"`을 추가한다. 옵션 적용 후 끊기면 옵션을 빼고 기본 연결부터 다시 확인한다. [scrcpy 사용 안내](https://github.com/Genymobile/scrcpy)

## 5. 연결이 끊기면

1. `adb devices -l`로 기기 연결 상태를 먼저 확인한다.
2. 목록이 비었다면 케이블·포트·USB 연결부터 점검한다. scrcpy만의 문제로 단정하지 않는다.
3. ADB는 정상인데 창만 실패하면 `scrcpy -V debug`의 최초 오류를 확인한다.
4. 다른 ADB 작업이 없는지 확인한 뒤 서버 재시작이 필요한 경우에만 아래 명령을 사용한다.

```sh
adb kill-server
adb start-server
adb devices -l
```

다른 기기의 ADB 작업도 끊길 수 있다. 연결 복구 후 scrcpy를 다시 실행한다. 특정 옵션·케이블이 원인인지는 같은 조건에서 한 번에 하나씩 바꿔 확인한다.

## 6. 무선 연결 — Android 11 이상

같은 Wi-Fi에서 폰의 개발자 옵션 → 무선 디버깅 → 페어링 코드로 기기 페어링을 연다. 아래 예시 주소·포트는 폰에 표시된 값으로 바꾼다.

```sh
adb pair 192.0.2.10:37000
adb connect 192.0.2.10:39000
adb devices -l
```

페어링 포트와 연결 포트는 다를 수 있다. mDNS로 자동 연결되면 `adb connect`가 필요 없을 수 있다. 연결 확인 뒤 대상 시리얼을 지정하고 scrcpy를 실행한다. [무선 디버깅 공식 안내](https://developer.android.com/tools/adb#connect-to-a-device-over-wi-fi)

화면 공유·녹화에는 알림·인증번호가 포함될 수 있다. 테스트 계정을 사용하고 공유 전 증거를 직접 확인한다.
