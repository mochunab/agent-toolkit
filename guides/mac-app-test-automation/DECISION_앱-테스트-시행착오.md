# 앱 테스트 자동화 — 범용 원칙과 레슨런

> 개인의 계정·기기·세션 이력 없이 재사용할 수 있도록 정리한 체크리스트.
> 개편 기준일: 2026-10-04.

## 0. 핵심 원칙

화면 읽기 → 한 번 조작 → 새 화면 확인을 반복한다. 설치됨·연결됨·실제 조작 성공을 구분한다. 처음에는 조회 중심 흐름으로 검증하고, 반복 회귀 테스트는 별도 도구와 안정성 측정을 계획한다.

## 1. 공통 결정사항

| ID | 원칙 | 이유 |
| --- | --- | --- |
| D1 | Android는 ADB 직접 조작, iPhone은 미러링 + Computer Use부터 검증 | 플랫폼별 연결 경로가 다름 |
| D2 | 승인된 시나리오의 중단 지점에서 멈춤 | 조회 테스트와 발송·결제 테스트를 구분 |
| D3 | 비교 대상의 조건을 맞춤 | 대상 차이를 앱 차이로 오해하지 않기 |
| D4 | 같은 입력값·초기 상태로 실행 | 재현 가능한 비교 |
| D5 | 관찰·해석·제공 정보·미확인을 구분 | 화면만으로 원인·영향 크기를 확정할 수 없음 |
| D6 | 증거는 단계별 번호와 상대 경로로 기록 | 다른 환경에서도 문서·증거 연결 유지 |
| D7 | 오류·정정은 근거와 함께 기록 | 이전 결론의 변경 이유 추적 |
| D8 | 공유 전에 캡처·XML·로그·파일명 점검 | 식별정보·인증정보 노출 방지 |
| D9 | 프로젝트별 결과와 범용 가이드를 분리 | 설치 안내에 특정 계정·운영 상태가 섞이지 않도록 |

## 2. 시행착오에서 얻은 점검 항목

특정 개인의 사건 기록 대신 문제 유형과 재발 방지 행동을 정리했다.

### 2-1. 방법·도구

| 문제 | 다음 행동 |
| --- | --- |
| Computer Use 연결 종료 | 설치·런타임·MCP·권한을 나눠 점검, 최초 오류 기록 |
| 스킬만 있고 실제 도구가 없음 | 서버 연결·새 세션 확인 |
| UI 요소 정보가 적음 | 웹뷰라고 단정하지 않고 화면 기반 점검 |
| 디버그 접속이 오래 멈춤 | 시간 한도 설정, 앱의 디버깅 지원 여부 확인 |
| 한글 입력이 안 됨 | 현재 입력 방법·키보드 확인, 기기별 좌표 재측정 |
| 축소 화면 좌표와 기기 좌표가 섞임 | 원본 크기와 환산 기준 명시 |
| 무한 스크롤 | 검색 우선, 횟수·시간·종료 조건 정의 |

### 2-2. 화면 조작

| 문제 | 다음 행동 |
| --- | --- |
| 재실행 후 이전 모드가 복원됨 | 입력 전에 앱·모드·계정 상태 확인 |
| 연속 탭 중 알림·다른 화면이 끼어듦 | 한 번 조작 후 새 화면 확인 |
| 빈 화면·로딩을 성공으로 처리 | 대기 한도와 BLOCKED/FAIL 기준 정의 |
| 운영 데이터가 보이는 계정으로 테스트 | 전용 계정·환경 사용, 범위 밖 동작 중단 |
| 앱을 다시 켰는데 상태가 달라짐 | 초기 상태·초기화 방법을 기록 |

### 2-3. 파일·정리

- 저장 후 실제 파일 목록·개수·상대 경로를 대조한다.
- 파일명은 실제 화면과 맞추고 사람·기기 식별자를 넣지 않는다.
- 변수 경로를 이용한 삭제는 빈 변수 여부와 대상을 확인하고 별도 단계로 처리한다.
- 자동 저장·변환이 일부 실패하면 누락된 산출물을 확인한다.

### 2-4. 개인정보

- 이름·닉네임·전화번호·계정·인증번호·개인 주문 정보가 보이면 공유 증거에서 제외하거나 가린다.
- 사용자 홈 경로·기기 시리얼·세션 ID·토큰은 자리표시자로 바꾼다.
- 가림 처리 후 이미지를 다시 열어 확인한다. 확인하지 않고 “모두 가림”이라고 쓰지 않는다.
- 공유용 안내에는 캡처 대신 시스템 설정의 메뉴 경로를 적는다.

### 2-5. 주장·숫자 검증

| ID | 실수 유형 | 규칙 |
| --- | --- | --- |
| V1 | 일부 화면만 보고 “없다” 단정 | 확인한 범위를 적고 전체 대상과 대조 |
| V2 | 비교 없이 “이 앱만” 주장 | 같은 조건에서 비교 대상 모두 확인 |
| V3 | 잘린 화면의 항목 누락 | 스크롤·펼치기로 끝까지 확인 |
| V4 | 암산·건수 재집계 오류 | 계산식과 근거 목록으로 다시 확인 |

## 3. 실행 체크리스트

### 시작 전

- [ ] 시나리오·입력값·기대 결과·중단 지점 확정
- [ ] 테스트 계정·앱 버전·OS·초기 상태 기록
- [ ] Android: 대상 기기 device 상태, 화면 켜짐·잠금 해제
- [ ] iPhone: 미러링 연결, Computer Use의 화면 읽기·입력 검증
- [ ] 캡처 좌표의 원본 크기·축소 비율 확인

### 진행 중

- [ ] 한 번 조작 → 새 화면 읽기 → 기대 결과 대조
- [ ] 앱 재실행 후 모드·상태 재확인
- [ ] 로딩·목록 수집의 시간 한도 준수
- [ ] 범위 밖 결제·발송·승인 동작 중단

### 저장·보고

- [ ] 기대 결과와 실제 결과를 구분하고 PASS/FAIL/BLOCKED 기록
- [ ] 숫자·건수·“없다/유일하다” 주장 재대조
- [ ] 증거·로그·파일명에서 개인 정보 제거 후 확인
- [ ] 상대 링크·이미지 파일 존재 여부 확인

## 5. 실행 기록

OS·호스트·앱 버전, 입력값, 기대/실제 결과, 최초 오류, 마지막 변경, 증거 경로를 남긴다. 다른 PC에서 설치·권한 상태를 그대로 가져갈 수 있다고 가정하지 않는다.
