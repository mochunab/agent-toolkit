# plain-writer

사람이 읽는 한국어 글을 **결론 먼저, 짧은 문장, 구체적인 말**로 쓰거나 고친다.
업무 메시지·보고서부터 모임 공지·집주인 문의·항의 이메일까지 같은 원칙을 쓴다.

판정 기준은 하나다. **받는 사람이 한 번 읽고 이해하고, 무엇을 해야 하는지 아는가.**

## 파일 구성

| 파일 | 내용 |
|---|---|
| `references/rules.md` | 글쓰기 규칙 정본 (분량·문장·용어·수식어·구조) |
| `references/channels.md` | 매체별 형식 (메신저·이메일·문서·공지·문의) |
| `references/checklist.md` | 퇴고 점검표 |

## 호출 형식

```
/plain-writer [draft|polish] [텍스트 또는 파일 경로]
```

슬래시 명령 없이 "이거 쉽게 고쳐줘"라고 해도 같게 동작한다.

## 모드 판별

모드 인자가 있으면 따른다. 없으면 아래 표로 정한다.

| 입력 특징 | 모드 |
|---|---|
| 메모·키워드·불릿, "~에 대해 써줘" 류 요청 | draft (새로 쓰기) |
| 완성된 문장 2개 이상 + "고쳐/다듬어/줄여/퇴고" 류 동사 | polish (고치기) |
| 판별 불가 | 1단계 확인 질문에 모드도 함께 묻는다 |

## 1단계: 받는 사람·매체·목적 확정

입력에서 다음 넷을 읽어 낸다.

- **받는 사람**: 누구인가 (상사·동료·고객·가족·모임 회원·관공서·처음 보는 사람)
- **매체**: 메신저·문자 / 이메일 / 문서·보고서 / 공지·안내문 / 문의·민원
- **목적**: 결정 요청 / 행동 요청 / 정보 공유 / 문의 / 항의·사과
- **기한**: 요청이면 언제까지

하나라도 읽어 낼 수 없으면 **한 번에 묶어 한 번만** 묻는다. 추측으로 진행하지 않는다.
글의 뜻이 갈리는 다른 빈칸(금액 단위, 장소, 대상)도 같은 질문에 넣는다.
이런 빈칸은 4번 뒤에 5·6번으로 이어 적는다.

```
글을 쓰기 전에 확인합니다.
0. 모드: 새로 쓰기 / 고치기 (판별 불가할 때만)
1. 받는 사람: ? (예: 모임 회원 / 집주인 / 팀장)
2. 매체: 단톡방 공지 (입력에서 확인)
3. 목적: 참석 여부 회신 요청으로 보입니다. 맞나요?
4. 기한: 언제까지 답을 받아야 하나요?
```

입력에서 읽은 값은 "(입력에서 확인)", 추정한 값은 "~로 보입니다. 맞나요?", 모르는 값은 "?"로 쓴다.
일상의 짧은 글이고 넷이 모두 분명하면 묻지 않고 바로 쓴다.

## 2단계: 모드별 절차

**draft**
1. `references/rules.md`와 `references/channels.md`의 해당 매체 절을 읽는다.
2. 규칙대로 쓴다.
3. `references/checklist.md`로 스스로 점검한다. "아니오"가 있으면 고친다.
4. 아래 '문장 점검'을 통과한 뒤 글만 출력한다. 점검 과정은 출력하지 않는다.

**polish**
1. `references/checklist.md`로 원문을 진단한다. "아니오" 항목을 적어 둔다.
2. `references/rules.md`와 해당 매체 절에 따라 고친다.
3. '문장 점검'을 통과한 뒤 아래 출력 형식으로 낸다.

## 문장 점검 (출력 전 필수)

제목·표 칸을 뺀 모든 문장을 하나씩 본다. 이 표는 내부 작업이며 출력하지 않는다.

| 문장 | 글자 수 | 두 사실을 접속어로 이었나? | 모호한 말이 있나? |
|---|---|---|---|

- 60자를 넘으면 나눈다.
- `~고/~며/~지만/~는데/~해서`로 사실 두 개를 이었으면 두 문장으로 나눈다.
  - 예: "비용이 낮고 2주면 끝납니다" → "비용이 낮습니다. 2주면 끝납니다."
- 모호한 말(빠르게·곧·많이·일부·상당히)은 입력에 있는 수치·날짜로 바꾼다. 없으면 지운다.
- 한 항목이라도 남으면 출력하지 않는다.

## 출력 형식

**draft**: 글만 낸다. 매체에 맞는 서식을 쓴다 (`channels.md`).

**polish**:

```
## 수정본
(바로 복사해 쓸 수 있는 형태)

## 바꾼 점
| # | 원문 | 수정 | 이유 |
|---|---|---|---|
| 1 | 확인이 진행될 예정입니다 | 제가 금요일까지 확인하겠습니다 | [문장] 행위자를 주어로 |
| 2 | 최대한 빨리 | 3일 안에 | [수식어] 모호어를 날짜로 |
```

- 끝내 확인하지 못한 점은 수정본 바로 아래에 `확인 필요: …` 한 줄로 적는다.
- 의미 있는 변경만 3~10개 적는다. 조사·어미 하나 바꾼 것은 빼고, 지운 인사말·관용구는 한 행으로 묶는다.
- 이유 칸은 `checklist.md` 태그(`[구조] [문장] [용어] [수식어] [화법] [받는 사람] [매체]`) + 한 구절.

## 사실 규칙

- 사실을 더하거나 바꾸지 않는다. 입력에 없는 수치·날짜·이름·금액을 만들지 않는다. 필요하면 1단계에서 묻는다.
- 상대 날짜(내일·이번 주 금요일)는 오늘 기준 절대 날짜와 요일로 바꾼다. 어느 주인지 모호하면 묻는다.
- 날짜와 요일이 서로 맞지 않으면 고치지 않는다. 요일을 빼고 `확인 필요`로 표시한다.
- 원문의 모호한 기한(이번 주 안에)과 명시된 날짜가 함께 있으면 명시된 날짜만 남긴다.
- 사용자가 준 고유명사·수치 표기는 그대로 둔다.
- 감정이 담긴 글(사과·항의·위로)은 감정을 지우지 않는다. 늘어진 표현만 줄인다.
