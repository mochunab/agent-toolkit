# 배포 보안 게이트

배포 직전 `security-review`에서 실행하고 `deploy-checker`가 최종 결과를 확인한다. 프로젝트의 AGENTS/CLAUDE와 기존 검사 명령을 먼저 읽는다. production 및 공개 preview에 적용하며, 비공개 로컬 작업에는 배포 게이트를 요구하지 않는다.

## 대상과 판정

- 절대 프로젝트 경로, Git SHA, 작업 트리 상태, 검사 시각, 배포 환경, 검사 URL을 기록한다. 모노레포는 저장소 전체 시크릿 검사와 배포 패키지 의존성/테스트 범위를 구분한다.
- Pass: 실제 검사 성공. Block: 취약점·금지 상태 발견. 미검증: 도구/권한/환경/증거 부족 또는 실행 실패. N/A: 해당 기능이 없다는 근거 기록.
- 필수 항목 Block 또는 미검증이면 배포 중단. 스캐너 미설치·timeout·registry 장애·테스트 skip·shallow clone은 통과가 아니다.
- production은 검토 가능한 커밋과 깨끗한 작업 트리를 기준으로 한다. 공개 preview가 변경 파일을 포함하면 그 파일도 검사하고, 변경 후 이전 결과를 재사용하지 않는다.
- 시크릿 원문은 결과·로그·첨부에 남기지 않는다. 자동 설치·업데이트·취약점 자동 수정·DB 정책 적용은 검사에 포함하지 않는다.

## 필수 검사

| 항목 | 검사 및 통과 기준 |
|---|---|
| 시크릿 | 승인된 스캐너로 전체 로컬 Git refs의 히스토리와 현재 배포 파일을 각각 검사. `git rev-parse --is-shallow-repository`가 true면 히스토리 검증 미완료. 발견 0건. `.env`/개인키 추적 여부와 Service Role Key의 클라이언트 코드·빌드 산출물 노출도 확인 |
| 의존성 | 프로젝트 패키지 매니저와 잠금 파일로 검사. npm 프로젝트는 `npm audit --audit-level=high` 등 기존 명령 사용. dev 도구도 검사하며 HIGH/CRITICAL 0건. 그 외 취약점은 영향·처리 일정 기록. 잠금 파일 누락·감사 실행 실패는 미검증 |
| SAST | 프로젝트 언어에 맞는 승인된 규칙으로 정적 분석. SQL 문자열 연결, 입력 미검증, HTML/스크립트 출력, 인증·시크릿 노출 등 확인. 차단 수준 발견 0건. 규칙 버전/범위 기록. 엔진 성공이어도 대상 언어를 스캔하지 않았다면 N/A 근거 또는 미검증 |
| 인증·권한 | 보호 API의 비로그인·만료/잘못된 토큰 거부, 다른 사용자 데이터 접근 거부, 일반 사용자의 관리자 기능 거부를 실제 테스트. 서버가 검증한 사용자 ID를 기준으로 권한 판정. 쿠키 인증 변경 요청은 CSRF 방어 확인 |
| Supabase/RLS | Supabase 사용 시 클라이언트 접근 테이블과 Storage의 정책을 기능별로 검사. 사용자 A/B와 비인증 역할의 읽기·쓰기 허용/거부를 격리된 테스트 환경에서 확인. RLS 활성화 여부만으로 Pass 금지. 공개 읽기는 설계에 맞게 허용하되 무단 쓰기는 거부 |
| 입력·노출 | 서버 입력 검증, 파라미터 바인딩, HTML 이스케이프/정화, 파일 업로드 제한을 코드와 관련 테스트로 확인. 사용자 응답의 상세 에러/스택·로그의 시크릿 노출 차단 |
| 헤더·HTTPS | 실제 preview/staging URL에서 CSP, nosniff, Referrer-Policy, Permissions-Policy 및 frame-ancestors/X-Frame-Options 확인. HTTPS·유효 인증서·TLS 설정 확인. 로컬 HTTP는 production TLS 증거가 아님 |
| CORS·남용 방어 | 인증 API의 허용/비허용 Origin을 실제 요청으로 검증. CORS는 인증을 대체하지 않음. 로그인·관리·비용 발생 API의 요청 제한을 위험도에 맞게 확인 |

검사 도구가 없는 항목은 설치 필요와 대안을 보고한다. 단순 grep은 히스토리 시크릿 스캐너나 SAST를 대체하지 않는다. 스캐너·규칙·예외 목록은 버전 고정/검토 대상으로 관리한다.

Gitleaks 사용 시 공식 CLI의 `git` 및 `dir` 명령을 구분하고 `--redact`를 사용한다. `git --log-opts="--all"`은 로컬에 가져온 refs만 검사하므로 full checkout 범위도 기록한다. Semgrep 등은 발견 시 비정상 종료하는 모드와 검토한 보안 규칙을 사용한다.

헤더는 리소스 종류·필요한 외부 도메인에 맞게 최소 허용한다. CSP의 `unsafe-eval`, 광범위 `https:` 허용을 기본값으로 복사하지 않는다. OAuth/임베드와 충돌하는 정책은 실제 동작으로 확인한다. TLS/헤더 점수는 참고 신호이며 인증·권한 검사를 대체하지 않는다.

## 실제 검증 경계

- 프로덕션 DB에 테스트 쓰기·정책 변경 금지. 격리 환경/테스트 계정이 없으면 권한 검증은 미완료로 보고한다.
- 보안 테스트를 위해 production 배포를 먼저 하지 않는다. 기존 staging/preview 또는 플랫폼 설정 증거를 사용한다. 새 배포가 필요한 검증은 별도 승인된 검증 배포에서 진행하고, 완료 전 production은 중단한다.
- 최초 검증 URL이 없다면, 승인된 배포 범위에 포함된 **접근 제한된 검증 preview**에서 확인한다. 시크릿·의존성·SAST·권한 등 URL 없이 가능한 필수 검사는 먼저 통과해야 한다. 접근 제한과 production 시크릿 미사용을 확인하고 검증 배포 → 해당 SHA의 헤더/TLS 검사 → 최종 판정 순서로 진행한다. 검증 완료 전 공개 preview/production으로 승격하지 않는다. 이미 승인된 검증 배포에 재승인을 요구하지 않는다. 접근 제한된 환경을 제공할 수 없다면 필수 검증 미완료로 중단한다.
- 외부 점수 사이트에 비공개 URL/코드를 보내거나 토큰 유효성 검증을 위해 외부 서비스에 전송하지 않는다. 외부 제출이 필요한 경우 별도 권한을 확인한다.

## CI와 배포 연결

- 프로젝트에 적용할 때 [CI 적용 계약과 템플릿](ci-gate.md)을 확인한다. 템플릿 보관은 실제 프로젝트 CI 적용/실행 완료를 뜻하지 않는다.
- PR과 production 대상 커밋에서 시크릿·의존성·SAST·보안 회귀 테스트를 실행한다. 경로 필터로 필수 검사가 생략되지 않게 한다. PR 코드는 production 시크릿 없이 검사한다.
- `continue-on-error`, `|| true`로 필수 검사 실패를 무시하지 않는다. 필수 job이 skip/cancel/failure면 배포 중단. `needs`로 필수 job에 의존하고 배포 커밋을 검사 커밋과 고정한다.
- 보호 브랜치에는 필수 보안 status check를 등록한다. 보안 workflow/규칙/예외 및 배포 설정 변경도 PR 검토 대상으로 관리한다.
- Vercel Git 자동 배포·다른 workflow·수동 CLI 배포는 `needs`만으로 차단되지 않는다. 모든 production 경로를 검증된 파이프라인으로 통합하거나 해당 플랫폼의 배포 차단 기능과 연결한다.
- 공개 preview도 보호 자료·production 시크릿을 포함하지 않게 하고, 보안 검사를 우회하는 공개 자동 배포 경로를 확인한다.
- CI 파일만 작성한 상태, CI 성공, required check 설정, 우회 경로 차단을 따로 보고한다. 실패 사례에서 배포가 실행되지 않는 실제 run을 확인해야 강제 차단 완료다.

## 결과 전달

```text
대상: 경로 / SHA / 작업 트리 상태 / 환경 / 검사 시각
판정: 배포 가능 또는 중단
항목별: Pass | Block | 미검증 | N/A — 명령/테스트, 종료 상태, 근거
차단/미검증: 항목과 해소 조건
경고: 낮은 심각도 항목, 영향 및 처리 일정
CI: 검사 run / 필수 check / 배포 연결 / 우회 경로 확인 상태
다음: deploy-checker에 동일 대상과 결과 요약 전달
```

코드·의존성·RLS/인증 정책·배포 설정이 바뀌면 관련 검사와 최종 `deploy-checker`를 다시 실행한다. Warning은 필수 미검증을 숨기는 용도로 쓰지 않는다.

도구 근거: [Gitleaks](https://github.com/gitleaks/gitleaks), [Semgrep CLI/CI](https://semgrep.dev/docs/semgrep-ci/sample-ci-configs).
