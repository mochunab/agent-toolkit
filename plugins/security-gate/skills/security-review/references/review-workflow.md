# 보안 점검 모드

"보안 점검해줘", "취약점 확인해줘", "CI 보안 상태만 확인"처럼 점검을 요청하면 실행한다. 결과는 실제 증거와 미검증 범위를 구분한다. 배포 요청이 있으면 별도의 [배포 게이트](deployment-gate.md)로 판정한다.

## 범위와 실행

1. 명시한 프로젝트 경로/저장소를 우선하고, 없으면 대화에서 확정된 현재 프로젝트를 사용한다. 홈 폴더나 참고 URL만 있고 프로젝트를 확정할 수 없으면 대상부터 확인한다. 여러 프로젝트를 임의로 묶어 검사하지 않는다.
2. AGENTS/CLAUDE/README, Git 상태, 패키지 매니저·잠금 파일, 기존 테스트·보안 검사·CI·배포 설정을 확인한다. 사용자가 코드만/설정만/읽기 전용으로 제한하면 그 범위에 맞춘다.
3. 기존 코드에서 입력 → 인증/권한 → 처리 → 저장 → 응답 흐름을 확인한다. 아래 항목은 프로젝트가 사용하는 기능에 맞게 검사한다. 정적 파일만 있는 프로젝트에 RLS 등 없는 기능을 요구하지 않는다.
4. 설치된 승인 도구와 기존 검사 명령을 실행한다. 테스트 실행 전 DB 쓰기·메일 전송·외부 변경 여부를 확인하고 안전한 격리 환경에서만 실행한다. production DB 쓰기, 테스트용 정책 변경, 위험한 외부 요청을 점검에 포함하지 않는다.
5. 도구 미설치·접속 권한 부족·실행 실패는 미검증으로 기록한다. 가능한 정적 검토는 계속하고, 실행하지 않은 스캔/권한 테스트를 성공으로 보고하지 않는다. grep만으로 전체 시크릿 스캔·SAST 완료라 하지 않는다.

## 검사 항목

- 시크릿: 코드·현재 파일·Git 히스토리·클라이언트 산출물의 키 노출, `.env` 추적, Service Role Key 사용 위치. 원문 시크릿 대신 파일 위치/탐지 종류/건수만 반환한다.
- 인증·권한: 서버 측 세션/JWT 검증, 관리자 권한, 다른 사용자 데이터 접근, Supabase 테이블·Storage RLS. 코드와 실제 격리 테스트 증거를 구분한다.
- 입력·출력: 서버 검증, SQL 파라미터 바인딩, HTML/XSS 방어, 파일 업로드 제한, 쿠키 기반 변경 요청의 CSRF 방어.
- API·브라우저: 인증 API CORS, CSP·보안 헤더·HTTPS/TLS, 필요한 외부 리소스 허용, 민감/비용 발생 기능의 요청 제한.
- 노출·의존성: 사용자 응답의 상세 에러, 로그의 개인정보·토큰, 잠금 파일, 의존성 감사와 SAST 결과.
- CI·배포: 검사 누락/실패 무시, required check, 검사 커밋과 배포 커밋 일치, 별도 자동 배포 경로. 저장소 YAML만 보고 플랫폼 설정까지 확인됐다고 하지 않는다.

배포 수준의 통과 기준이 필요하면 [배포 게이트](deployment-gate.md)를 참조한다. 일반 점검에서는 자료 부족을 취약점 확정과 혼동하지 않는다.

## 변경 경계

- 기본 점검은 코드·의존성·CI·호스팅 설정·DB 정책을 수정하지 않는다. 점검 도구를 자동 설치하거나 취약점 자동 수정 명령을 실행하지 않는다.
- "고쳐줘"가 함께 승인됐으면 재현/원인 확인 후 해당 수정 범위로 진행한다. 새 외부 의존성은 이유·대안·영향을 먼저 제시하고 기존 승인을 확인한다.
- 스캐너의 시크릿 원문·토큰·사용자 데이터는 콘솔/결과/첨부에 노출하지 않는다. 스캐너 마스킹 옵션을 확인한다.
- 사설 URL/소스코드를 외부 분석 서비스에 제출하는 작업은 점검과 별도로 권한을 확인한다. 이미 승인된 도구·대상·작업은 재확인하지 않는다.

## 보고

대상과 Git SHA/작업 트리 상태, 점검 범위, 실행 명령과 결과를 기록한다. 발견한 위험이 먼저 보이게 정리한다.

| 필드 | 내용 |
|---|---|
| 발견 | 심각도, 파일/설정 위치, 실제 취약 조건과 영향 |
| 증거 | 코드 근거 또는 실행 결과. 정적 의심과 실제 재현을 구분 |
| 미검증 | 도구/권한/테스트 환경 부족 및 해소 조건 |
| 권고 | 위험을 줄일 수정안과 우선순위 |
| 적용 상태 | 점검만 완료 / 승인된 수정 반영 / CI 연결 확인 상태 |

발견 0건이어도 실행하지 않은 검사가 있으면 "전체 보안 통과"라 하지 않는다. 일반 점검 결과를 배포 승인으로 바꾸거나, CI 파일 존재를 강제 차단 완료로 바꾸지 않는다.
