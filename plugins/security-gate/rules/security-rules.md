# 보안 규칙 (security-gate)

> security-gate 플러그인이 세션 시작마다 이 규칙을 컨텍스트에 넣는다. 플러그인 설치 시 스킬·에이전트 이름은 `security-gate:security-review`, `security-gate:deploy-checker`다.
> 수동 설치라면 필요한 부분을 프로젝트 또는 사용자 전역의 `CLAUDE.md`·`AGENTS.md`에 병합한다. 파일 전체를 덮어쓰지 않는다.
> 시크릿 평문 명령·공개 저장소 생성·보호 파일 직접 수정은 플러그인 훅이 실제로 차단한다. 차단되면 우회하지 말고 안내된 방법을 따른다.

## 요청 라우팅

- 보안 점검·검토·취약점 확인 → `security-review` 점검 모드. 기본 읽기 전용
- "프로젝트에 보안 연결해줘", "배포 전에 보안 검사하게 해줘", "보안 문제 있으면 배포 막아줘" → 같은 스킬의 CI 적용 모드. 사용자에게 CI 용어를 요구하지 않는다
- "보안 연결돼 있는지만 확인해줘" → 점검 모드. 설정 변경으로 확대하지 않는다
- 인증·권한·시크릿·입력·API·결제 작업 → 같은 스킬의 보안 기준을 적용하며 구현

## 배포 보안 게이트 (필수)

- 배포 요청에는 `security-review` 스킬 → `deploy-checker` 에이전트 순서로 점검한다. 이미 승인된 배포 작업에서는 단계마다 재승인을 묻지 않는다. 사용자가 점검을 중단하면 배포도 중단한다
- 판정 기준은 `security-review` 스킬의 `references/deployment-gate.md`다. 필수 항목은 실제 검사 명령·종료 상태·테스트 결과로 판정한다
- Block 또는 필수 항목 미검증이면 중단한다. 도구 미설치·실행 실패·권한 부족·shallow Git history를 Pass로 바꾸지 않는다. N/A는 기능 부재 근거를 기록한다
- 최종 검사 대상과 실제 배포 대상(커밋·작업 트리·환경)이 같아야 한다. 코드·의존성·DB 정책·배포 설정이 바뀌면 영향받는 검사와 최종 게이트를 다시 실행한다
- CI 검사 job 추가만으로 배포 차단 완료라 하지 않는다. 배포 job 의존성·동일 커밋·호스팅 자동 배포 등 우회 경로까지 확인한다
- 검증된 CI production 경로가 있으면 직접 CLI 배포로 우회하지 않는다
- 의존성 HIGH/CRITICAL: 런타임 패키지는 예외 없이 수정한다. `npm audit fix`(`--force` 없이)로 풀리는 것은 먼저 업데이트한다. major 업그레이드가 필요한 빌드·개발 전용 패키지만 근거·만료일(최대 90일)·사용자 승인이 있는 예외를 허용한다(게이트 문서의 「의존성 예외」)

## 절대 금지

- API 키·시크릿·토큰 하드코딩 → 환경변수 사용
- 라이브 시크릿을 명령 인자나 변수 할당으로 평문 노출하지 않는다(대화 기록·셸 히스토리에 남음). OS 키체인·시크릿 매니저에 저장하고 필요할 때 읽는다
- 도구 출력으로 받은 시크릿을 화면에 표시하거나 응답으로 반환하지 않는다
- `error.message`를 사용자에게 직접 보여주지 않는다 → 일반 메시지 표시, 상세는 서버 로그
- `.env` 커밋 금지. `.gitignore`만 믿지 않는다 — 서비스 키·PAT·서비스 계정 키 같은 자격증명은 Git 작업 폴더 밖(키체인·시크릿 매니저)에 둔다
- 새 저장소는 공개 의도가 확인되지 않으면 비공개로 만든다
- 외부 이미지·스크립트 URL을 검토 없이 추가하지 않는다(CSP 위반·공급망 위험)

## 입력값과 API

- 사용자 입력은 서버에서 재검증한다. 클라이언트 검증만으로 충분하지 않다
- SQL은 파라미터 바인딩을 사용한다(문자열 연결 금지)
- HTML 출력은 이스케이프·정화한다(XSS 방지)
- 인증·세션·토큰을 사용하는 API의 CORS는 Origin 허용 목록을 쓴다(`*` 금지). 인증 없는 공개 리소스는 요구사항에 따라 `*` 허용
- 인증이 필요한 엔드포인트는 서버에서 JWT/세션을 검증한다
- 로그인·관리·비용 발생 API는 요청 제한(rate limiting)을 둔다

```ts
// ✅
console.error('[기능명] 에러:', error);
showError('처리에 실패했습니다. 다시 시도해주세요.');

// ❌ 내부 정보 노출
showError('실패: ' + error.message);
```

## 사고 대응

- API 키 유출: 즉시 교체(로테이션) → 호스팅 플랫폼 Secrets 갱신
- `.env` 커밋: `git rm --cached` → `.gitignore` 보강 → 시크릿 교체. 이력에 남은 값은 이미 유출된 것으로 본다
- 의존성 취약점: 정기 감사, critical/high 우선 패치
