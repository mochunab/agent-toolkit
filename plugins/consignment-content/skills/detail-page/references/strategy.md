# 상세페이지 작성 전략서

> 목적: 상품별로 첫 화면과 설득 순서를 결정하고, 촬영·초안·검수까지 실행한다.
> 독자: 상품을 선정하고 상세페이지를 기획·제작할 작업자.
> 출처: 위탁판매 작업 문서(2026-10 작성·갱신)에서 공개 가능한 부분. 후보 상품별 조사 표·경쟁 상세 캡처·공급처 원문·내부 손익 문서는 포함하지 않는다. 날짜가 적힌 수치·사례는 작성 시점의 관찰이며 그대로 재사용하지 않는다.
> 상태: 관찰을 바탕으로 만든 작성 전략. 공급 상품·성능·자사 전환 효과는 별도 검증 대상이다.
> 자매 문서: 이미지 시안의 흐름·모양·제작 절차는 [디자인 가이드](design-guide.md), 배운 원칙은 [제작 레슨런](lessons.md), 작업별 결정 과정은 [디자인 결정 기록](decision-log-template.md). 내용·증거 기준은 이 문서가 우선한다.

## 1. 무엇부터 결정할까

**고객의 구매 망설임 하나를 정하고, 그것을 해소하는 장면과 증거를 먼저 보여준다.**

가격이 높고 경쟁이 치열하며 고객의 비교 부담이 큰 상품은 “내가 겪는 문제가 어떻게 달라지는가”와 “이 상품을 선택할 이유”를 연결한다. 제품 특징은 그 변화를 가능하게 하는 근거로 설명한다. 익숙한 제품을 다시 사는 고객은 정확한 종류·규격·수량·구매 조건을 빨리 확인하게 한다.

가격만으로 고관여·저관여를 나누지 않는다. 저렴한 뜨개 키트도 완성 실패가 걱정되고, 고무패킹도 잘못 사면 설치할 수 없다. 같은 수건도 첫 구매와 재구매의 상세페이지가 달라진다. 이 판단의 관찰 근거는 조사 보고서에 있다.

기존 가이드의 용도·규격·구성·관리·배송 항목은 **빠뜨리지 않을 정보 목록**으로 활용한다. 본문 순서는 아래 기준으로 선택한다.

착수 전에 다음 네 줄을 채운다. 빈칸이 있으면 카피보다 확인 작업을 먼저 한다.

| 결정할 것 | 작성 방식 |
|---|---|
| 고객·상황 | “[누가] [언제·어디서] [무엇을 하려는가]” |
| 원하는 변화 | 사용하는 동작·완성 결과·선택 시간처럼 보여줄 수 있는 변화 하나 |
| 구매 망설임 | “내 환경에 맞나 / 내가 할 수 있나 / 품질이 맞나 / 같은 제품인가” 중 우선 질문 하나. 4절의 확인된 불만이 있으면 거기서 고른다 |
| 선택할 이유 | 해당 공급 상품에서 확인된 차이와 그것을 보여줄 자료 |

“삶의 질 향상”, “최고의 품질”만으로 끝내지 않는다. 예를 들어 ‘현관에서 구두주걱을 찾는 상황 → 정해진 위치에서 바로 꺼내는 동작 → 실제 부착 구조’로 구체화한다. 지원하는 기능과 표면 조건은 공급품에서 확인한다.

## 2. 어떤 설득 순서를 선택할까

아래는 작성용 기본안이다. 고객 질문에 따라 섞을 수 있다. 호환·미포함 구성·도착 조건처럼 구매 실패를 만드는 정보는 선택한 흐름에서도 앞당긴다.

| 유형 | 선택하는 상황 | 첫 화면 | 본문 순서 |
|---|---|---|---|
| A. 문제·변화 | 불편은 알지만 이 제품의 필요성·차이를 모름 | 실제 사용 결과와 바뀌는 동작 | 상황·원하는 결과 → 작동 장면 → 차이를 만드는 구조 → 조건을 적은 증거 → 옵션·구성 → 사용·관리 |
| B. 성취·실패 방지 | 완성·선물·행사 성공이 중요함 | 완성 모습과 성공 조건 | 원하는 결과 → 난이도·준비물·납기 → 따라 하는 과정 → 포함/미포함·선택 → 실패 방지·FAQ |
| C. 호환·선택 실패 방지 | 설치·규격·기기·표면에 따라 사용 가능 여부가 달라짐 | 사용 목적과 맞는 조건·맞지 않는 조건 | 환경 확인 → 규격·옵션 선택 → 설치·사용 시연 → 조건별 검증 → 관리·주의 |
| D. 익숙한 제품 재구매 | 무엇을 살지 이미 정했고 구매 조건을 비교함 | 정확한 상품·규격·수량·배송 포함 조건 | 제품 식별 → 옵션·구매 조건 → 공급·소비기한·배송 정보 → 필요한 사용·교체 안내 |
| E. 첫 품질·취향 구매 | 핏·촉감·색·맛·공간 모습을 비교함 | 실제 착용·사용·음식 장면 | 기대 모습 → 선택 가이드 → 소재·실측·사용 근거 → 관리·구성 |

비싸거나 경쟁 상품이 많은 경우에는 A·E의 ‘차이를 만드는 이유’와 ‘증거’를 강화한다. 경쟁사보다 낫다는 말 대신, 고객이 중요하게 여기는 조건에서 확인된 차이를 보여준다. 차이가 확인되지 않으면 비교 우위 문구를 만들지 않는다.

같은 상품에 첫 구매·재구매 고객이 섞이면 먼저 주요 유입 고객을 정한다. 첫 구매 설명 아래에 재구매 고객이 바로 찾을 옵션 요약을 두거나, 재구매 요약 뒤에 처음 쓰는 고객 안내를 둔다. 본문 첫머리에서 같은 내용을 두 번 반복하지 않는다.

## 3. 첫 화면과 각 구간은 어떻게 작성할까

여기서 첫 화면은 네이버 공통 가격·옵션 영역 다음에 나오는 **판매자가 작성하는 본문 시작 부분**이다. 공통 구매 영역과 본문의 상품·옵션·가격 조건이 일치해야 한다.

첫 화면에는 다음을 넣는다.

- 한 문장: 고객의 상황과 기대 결과, 또는 정확한 재구매 제품 식별.
- 주 이미지: 판매하는 옵션의 실물·착용·사용·완성 장면. 사진만으로 제품과 사용 목적을 알 수 있게 한다.
- 결정 정보: 호환·규격·구성·미포함 도구·납기 중 구매를 막는 핵심 조건. 길면 선택표로 바로 연결한다.

관련 없는 행사 공지·다른 상품 홍보로 시작하지 않는다. 일정이나 출고 제한이 구매에 직접 영향을 주면 먼저 알려준다. 옵션이 많은 상품은 모든 이미지를 길게 나열하기 전에 선택 기준을 준다.

본문은 **한 구간에 구매 질문 하나**를 해결한다.

| 구간 구성 | 작성 기준 |
|---|---|
| 고객 질문 | “우리 식탁에도 붙나?”처럼 실제로 판단해야 할 질문 |
| 답 | 확인된 조건을 한 문장으로 요약 |
| 시각 자료 | 표면별 시연, 치수 사진, 실제 구성처럼 답을 확인할 자료 |
| 조건·제한 | 적용 모델·옵션·시험 환경·미포함품을 해당 주장 가까이에 표시 |
| 다음 행동 | 내 환경 측정, 옵션 선택, 조립법 확인 등 다음 결정을 안내 |

문제 장면을 과장해서 오래 끌지 않는다. 결과 장면을 보여준 뒤 “왜 가능한가”를 제품 구조·소재·작동으로 연결한다. 사진으로 확인할 수 없는 촉감·맛·안전성은 분위기 이미지와 검증 자료를 구분한다.

페이지 길이는 해결할 질문 수로 정한다. 같은 착장·특징·후기를 반복해 늘리지 않는다. 중요한 치수와 제한은 이미지 속 작은 글자로만 넣지 말고 모바일에서 읽을 수 있는 설명·표로도 제공한다.

### 문장은 어떻게 쓸까

**특징을 설명하지 말고, 그 특징 때문에 고객이 덜 하게 되는 행동을 쓴다.** 각 구간의 ‘답’ 문장은 확인된 특징 하나에서 “그래서 뭐?”를 세 번 묻는다. ① 특징이 직접 가능하게 하는 것 → ② 줄어드는 행동·시간·부담 → ③ 고객 상황에서 달라지는 관찰 가능한 행동. 마지막은 감정이 아니라 행동으로 쓴다(“마음이 편해요” ✗ / “매번 찾으러 가지 않아도 돼요” ✓).

| 유형 | 첫 화면 문장 틀 | 문장 작성 방식 |
|---|---|---|
| A. 문제·변화 | [상황]에서 [줄어드는 행동] | 특징 → 행동 변화로 번역 |
| B. 성취·실패 방지 | [완성 결과]를 [성공 조건]으로 | 완성 결과 + 실패를 줄이는 조건(포함 도구·난이도·납기) |
| C. 호환·선택 실패 방지 | [내 환경 조건]이면 맞아요 / 먼저 [측정할 것]을 확인하세요 | 혜택보다 맞는 조건과 맞지 않는 조건 |
| D. 익숙한 제품 재구매 | [제품명] [규격] [수량] | 혜택 문장 대신 식별 정보. 행동 변화 문장은 아래 구간에서만 |
| E. 첫 품질·취향 구매 | [사용 장면] + [고르는 기준] | 촉감·맛·핏을 단정하지 않고, 실측·소재·세탁 근거로 고르는 행동을 씀 |

| 확인된 특징 | 그래서 뭐? ①→②→③ | 문장 | 바로 아래 조건 |
|---|---|---|---|
| 현관 부착형 구두주걱 | 정해진 자리에 걸림 → 찾는 동작이 줄어듦 → 신발 신을 때 바로 꺼냄 | 신발 신을 때마다 찾지 않고, 현관 같은 자리에서 바로 꺼내 쓸 수 있어요. | [부착 가능한 표면] · 철판 [포함/별도] |
| 뜨개 키트 [코바늘 포함 확인 시] | 도구까지 들어 있음 → 따로 살 것이 없음 → 받은 날 바로 시작 | 도구를 따로 사지 않고, 받은 상자 안 재료로 바로 시작할 수 있어요. | 포함 구성 [목록] · 별도 준비 [없음/목록] |

두 예시는 문장 구조를 보여주는 기획 예시이며 대괄호를 채우기 전 등록 문구로 쓰지 않는다. 두 번째 예시는 코바늘 포함이 확인될 때만 성립한다. 미포함이면 같은 자리에 “코바늘은 별도 준비”를 쓴다. 특징이 바뀌면 문장도 바뀌며, 확인되지 않은 특징으로 행동 변화를 만들지 않는다.

- 한 문장에 혜택 하나. 본문 문장의 어미는 한 페이지 안에서 `~해요`로 통일한다. 이미지 속 제목·스티커는 짧은 구어체(“꾹! 꾹! 눌러 끼우면 끝”, “자르기 전에, 한 줄 먼저!”)를 쓸 수 있다. 구어체에도 효과·최상급 표현은 넣지 않는다.
- 상황어(현관에서, 출근 준비 때, 행사 당일)를 문장 앞에 둔다. 상황어도 1절 ‘고객·상황’에 적은 것만 쓴다.
- 명사 나열(“간편·신속·편리”)과 추상어(프리미엄·최고의·완벽한·특별한 경험·차원이 다른)는 쓰지 않는다.
- 최고·1위·유일·100%·효과 보장·부작용 없음은 해당 공급품의 인증·시험성적서가 있을 때만, 출처와 함께 쓴다.
- 숫자·비교 기준값은 원문·실측에 있는 것만 쓴다. “30분 걸리던 걸 3분에”처럼 비교 대상을 만들지 않는다.
- 경쟁 상품이 그대로 가져다 써도 맞는 문장이면, 우리 공급품에서 확인한 조건을 넣어 다시 쓴다.

초안은 AI에게 8절 양식으로 요청해 만들 수 있다. 입력은 1절 ‘고객·상황’과 6절 기준을 통과한 특징만 넣고, 행동·근거·숫자·금지어·장면·차별 자체 검수표를 초안 파일에 함께 남긴다.

## 4. 후보 상품의 고객 불만은 어떻게 쓸까

원본 문서의 후보 16개 용도별 조사 표(상품별 고객 불만·핵심 증거)는 소싱 후보 정보라 공개본에 싣지 않았다. 아래는 그 표를 만들고 쓰는 기준이다. 각자의 후보로 같은 표를 만든다.

| 후보 용도 | 기본 유형·첫 화면 | 확인된 고객 불만 → 첫 화면에서 답할 질문 | 구매 전 확보할 핵심 증거 |
|---|---|---|---|
| [용도] | [A~E 중 선택 + 첫 화면] | [같은 용도 상품의 1~3점 리뷰에서 확인한 불만, 없으면 ‘미조사’] | [시연·실측·원문 중 구매 전에 확보할 것] |

- 불만은 구매자 진술이며 결함 발생률이 아니다. 다른 판매자 상품의 리뷰이므로 우리 공급품에서 같은 문제가 해결됐는지 확인한 뒤에만 “해결” 문구를 쓴다. 해결을 확인하지 못하면 “우리 제품은 다르다”는 식으로 불만을 언급하지 않고 해당 조건(관리법·출고일 등)만 정확히 안내한다.
- 표의 시연·실측은 **앞으로 우리 공급품에서 확보할 자료**이며, 이미 검증된 기능 목록이 아니다.
- **‘미조사’ 용도는 초안 전에 같은 용도 상품의 1~3점 리뷰를 먼저 확인한다.** 리뷰 근거 없이 정한 망설임은 관찰 기반 가설로 표시한다.

**예외 — 구매 전 확인으로 막을 수 있는 선택 실패.** 규격·호환·치수를 확인하지 않아 생긴 불만(“두꺼워서 문이 안 닫혀요”, “치수 보고 샀는데 안 맞아요”)은 “주문 전에 이것을 확인하세요” 안내의 근거로 언급할 수 있다. 이때 우리 제품이 해결했다고 쓰지 않고, 수치는 6절 ‘상품군 후기 분석 수치’ 기준을 따른다. 품질·성능 불만(찢어짐·냄새·효과 없음)은 이 예외에 해당하지 않는다. 사례: [현관문 시안 v2 3번 섹션](../assets/sample/현관문_시안예시/상세페이지.html).

## 5. 실제 초안은 어떤 모습일까

아래는 흐름을 보여주는 기획 예시다. 대괄호는 공급처·샘플에서 확인할 값이며, 채우기 전 등록용 문구로 쓰지 않는다. 직접 찍은 실물 완성작·설치·시연 사진은 6절 2단계 이상 자료다. 1단계로 등록할 때는 공급처 허용 이미지로 대체한다. 공급처 설치 사진은 **사용 방법 안내**(빼기·끼우기·확인 순서)로는 쓸 수 있지만, 성능을 증명하는 시연·전후 비교로는 쓰지 않는다. 성능 시연 구간은 비워둔다.

### 뜨개 입문 키트: 완성하고 싶은 마음과 실패 걱정

1. 첫 화면: 판매 키트로 만든 실제 완성작 + “[완성 대상]을 직접 만드는 [키트명]”.
2. 바로 다음: “[확인된 난이도] / 기본 구성 [목록] / 별도 준비 [도구]”. 제작 시간은 관찰 자료가 있을 때 조건과 함께 표시.
3. 과정: 시작·중간·마무리 사진, 막히는 단계와 제공하는 안내.
4. 이유와 증거: 이 구성으로 무엇을 만들 수 있는지, 해당 옵션의 실제 제작 기록.
5. 선택·마무리: 색·수량·추가 도구 → 관리·주의 → 배송·문의.

판단 기준: 완성작이 예쁜지만 보지 않고, 처음 보는 고객이 필요한 도구와 따라 할 방법을 설명할 수 있는지 확인한다.

### 고무패킹: 선택과 설치의 불확실성

1. 첫 화면: 직접 교체하는 동작 한 문장(“현관문 패킹, 직접 갈아 끼우세요”) + 제품 사진 + 구성·단면 띠 + “홈 있는 문 전용” 조건. 조건을 먼저 묻는 안(“먼저 [홈 유무·단면]을 확인하세요”)은 10절 비교 실험의 비교안으로 둔다.
2. 도입: 교체 시기 자가진단 → 선택 실패 후기 수치(4절 예외·6절 기준) → “주문 전 3가지 확인”.
3. 선택: 문 사진·측정 위치 → [확인 치수]에 맞는 옵션 → 필요한 길이 계산 방법.
4. 시연: 설치 순서 → 설치 후 문 닫힘 → 사용 가능한 환경·제한. 1단계에서는 공급처 설치 사진으로 사용 방법만 안내.
5. 근거: 외풍 관련 주장은 확인한 방식·조건·결과가 있을 때만 제시.
6. 마무리: 구성·절단/관리·주의 → 배송·문의.

실제 구현 예시(공급처 사진은 자리표시 이미지로 바꿈): [현관문 시안 v2](../assets/sample/현관문_시안예시/상세페이지.html).

판단 기준: 고객이 주문 전에 자신의 문에서 무엇을 측정해야 하는지 알 수 있어야 한다.

### 롤클리너 리필: 같은 제품을 빨리 찾기

1. 첫 화면: 실물 포장·리필 + “[용도] / 폭 [값] / 내경 [값] / [길이] × [롤 수]”.
2. 구매 조건: 호환 본체·옵션별 구성·배송 포함 조건. 가격은 실제 판매 설정과 일치하도록 관리.
3. 차이: 사양 변경이 있으면 이전 제품과 달라진 점, 처음 쓰는 고객을 위한 사용 장면.
4. 사용: 교체법·사용 가능한 표면·주의 → 배송·문의.

판단 기준: 기존 고객이 긴 청소 이야기를 읽기 전에 자신이 찾는 규격과 수량을 구분할 수 있어야 한다.

## 6. 어떤 주장에 어떤 증거가 필요한가

| 말하려는 내용 | 확보할 자료 | 작성 기준 |
|---|---|---|
| 구성·치수·중량·소재 | 해당 옵션 원문, 실물 구성·측정 사진 | 측정 방법·단위·차이 범위를 확인. 다른 옵션 값을 혼용하지 않음 |
| 흡착·거치·호환·배수 | 실제 공급품 시연, 기기·표면·설치 조건 | 되는 조건과 안 되는 조건을 주장 가까이에 표시 |
| 흡수·세탁·내구 비교 | 같은 조건의 전후 기록, 비교 대상·방법 | 관찰한 범위로 표현. 확인하지 않은 우월성·수명 수치 생성 금지 |
| 안전·시험·인증 | 해당 모델 자료와 적용 범위·확인 정보 | 표시 이미지가 있다는 사실만으로 검증 완료 처리하지 않음 |
| 정품·공식판매처·소비기한 | 실제 공급 경로·판매 권한·현재 공급 정책 | 경쟁사 공식판매점 표현을 복사하지 않음 |
| 고객 후기·판매 성과 | 우리 상품의 실제 자료와 집계 조건 | 경쟁사 리뷰·순위·합산 판매량을 우리 성과로 사용하지 않음 |
| 출고·도착·반품 | 공급처 조건, 마켓 설정, 실제 처리 확인 | 출고 예정과 도착 보장을 구분. 확인하지 않은 날짜 약속 금지 |
| 상품군 후기 분석 수치(공감·선택 실패 예방 근거) | 우리가 읽고 분류한 기록: 대상 상품 수·평점 범위·건수·분류 기준·조사일 | 출처·분류 기준을 각주로 공개. 애매한 후기는 빼고 보수적으로 셈. 경쟁사 이름·후기 원문 캡처는 싣지 않음. 우리 제품이 해결했다고 쓰지 않음. 원문 대조 없이 요약을 기준으로 셌다면 그 사실을 기록 |
| 상담·교환·사진 확인 등 운영 약속 | 담당자·응답 시간·처리 범위 결정 | 운영 방식을 정하기 전에는 게시하지 않음. 응답 시간 문구는 실제 운영 기준과 일치 |

이미지는 공급처가 허용한 자료 또는 직접 촬영한 자료를 사용한다. 경쟁사 캡처는 기획 연구 자료다. AI로 다시 그린 제품이나 생성한 고객 반응을 실물·실제 후기 증거로 제시하지 않는다.

자료가 부족하면 해당 주장·비교는 제외하고 필요한 측정·촬영을 목록에 남긴다. 물건 자체의 주요 기능·구성·권리·판매 조건이 불명확하면 상품 등록을 보류한다.

### 샘플 없이 어디까지 쓸 수 있나

무재고 위탁은 재고를 사지 않으므로, 모든 상품에 직접 촬영·시연을 요구하면 대부분 등록이 보류된다. 확보한 자료 단계에 맞춰 **쓸 수 있는 주장의 범위**를 정하고, 단계가 오르면 페이지를 보강한다.

| 단계 | 확보 자료 | 쓸 수 있는 내용 | 쓰지 않는 내용 |
|---|---|---|---|
| 1. 공급처 자료 | 공급처 원문·허용 이미지·옵션 규격·구성·배송/반품 조건 | 원문에 적힌 규격·구성·소재·호환 목록, 허용 이미지, 배송·반품 조건. 첫 화면에는 유형별 결정 정보를 반드시 넣음(효과가 아닌 원하는 동작 문장과 함께 쓸 수 있음) | 시연·전후 비교·성능 문구. 원문의 성능 주장도 시험성적서 등 근거 자료가 없으면 제외 |
| 2. 샘플 확인 | 해당 옵션 샘플 1개의 실측·구성·실물 색·장착/부착 사진 | 1단계 + 직접 잰 치수, 실제 구성 사진, 확인한 기기·표면에서의 장착 결과(조건 병기) | 반복 세탁·내구 결과, 확인하지 않은 기기·표면으로의 일반화 |
| 3. 반복 시험·판매 후 | 세탁 전후·표면별 시연 기록, 실제 주문 문의·반품 사유 | 2단계 + 조건을 적은 시험 결과, 4절 불만에 대한 “확인한 범위의 해결” 문구 | 시험 범위 밖 수명·우월성 수치 |

- 유형별 최소 단계: D(재구매)는 1단계로 등록 가능. C(호환)는 공급처 호환 목록이 구체적이면 1단계, 없으면 2단계. A·B·E는 1단계로 등록할 수 있으나 4절 불만을 첫 화면에서 다루려면 2단계 이상.
- 샘플 구매비·배송비·작업시간은 상품별 손익에 넣는다. 후보가 여러 개면 상품별 남는 금액을 먼저 비교한 뒤 샘플을 산다.
- 초안 파일 상단에 현재 단계를 적고, 단계가 오를 때 추가한 문구와 날짜를 기록한다.

## 7. 기획부터 검수까지 어떻게 진행할까

| 순서 | 작업 | 완료 신호 |
|---|---|---|
| 1. 공급품 확인 | 한 상품·한 옵션의 원문, 공급/판매 조건, 이미지 사용 범위 확보 | 판매할 물건과 구성·권한·배송·반품 조건을 설명할 수 있음 |
| 2. 고객 질문 선택 | 검색 의도·4절의 확인된 불만을 바탕으로 상황과 망설임 하나 작성. 미조사면 1~3점 리뷰 먼저 확인 | 왜 이 유형을 골랐는지 한 문장으로 설명 가능 |
| 3. 흐름 결정 | A~E 중 기본 유형 선택, 실패 정보 위치 결정 | 첫 화면과 각 구간의 질문·답이 확정됨 |
| 4. 증거 준비 | 6절 증거 단계 결정, 구간별 사진·측정·시연·원문 연결. 샘플이 필요하면 비용을 손익에 반영 | 현재 단계와 그 단계에서 쓸 수 있는 주장·미확인 주장이 구분됨 |
| 5. 초안 작성 | 확인된 자료로 3절 문장 기준에 맞춰 카피·이미지 설명·옵션 표 작성 | 모든 사실 문구가 해당 옵션의 근거에 연결됨 |
| 6. 이미지 시안 | 같은 상품군 리뷰 많은 순 상위 3~5개 상세를 끝까지 보고 첫 화면·근거 없는 주장을 확인한 뒤, [디자인 가이드](design-guide.md)의 흐름·모양·제작 절차로 섹션별 이미지 제작. 핵심 치수·옵션표·제한은 글자·표로도 준비 | 섹션 이미지 전체 검수·금지어 검사·숫자 대조 통과 |
| 7. 대조·모바일 검수 | 공급처 원문·샘플·상품명·옵션·가격·고시·배송 대조 | 아래 검수 항목 통과. 불일치 시 수정 후 재확인 |
| 8. 게시·관찰 | 검수한 버전으로 등록 후 실제 표시와 문의 확인 | 게시본도 동일 조건이며 변경 전후 버전·날짜를 기록함 |

촬영 목록은 ‘예쁜 제품 사진’ 대신 **어느 질문을 증명할 사진인가**로 작성한다. 예: 전체 구성 한 장, 측정 위치 한 장, 작동 전후 같은 각도, 호환되지 않는 환경과 그 이유. 단계마다 옵션명과 촬영 조건을 기록한다.

## 8. AI 초안 요청에 무엇을 넣을까

아래 양식을 복사해 상품별로 채운다. 원문·샘플 확인 전에는 구성안을 만드는 용도로 사용한다.

```text
상품/공급처 URL·옵션 식별번호:
주요 고객·검색 의도:
사용 상황:
원하는 변화:
가장 큰 구매 망설임·근거 불만(출처):
증거 단계(1 공급처 자료 / 2 샘플 / 3 반복 시험):
선택 유형(A~E)·선택 이유:
확인된 차이와 근거:
구성·미포함품·규격·호환·소재:
배송·반품·가격 조건:
사진/시연/측정/허용 이미지 목록:
미확인 사항·추가 촬영/확인할 항목:

위 자료로 첫 화면과 본문 구간별 기획안을 작성해줘.
각 구간은 고객 질문 / 핵심 문장 / 시각 자료 / 근거 / 조건·제한으로 작성해줘.
확인된 특징을 고객의 동작·선택·완성 결과와 연결해줘.
핵심 문장은 특징 → 그래서 뭐? 3회 → 관찰 가능한 행동 변화로 쓰고, 한 문장 한 혜택·~해요 어미로 통일해줘.
추상어(프리미엄·최고의·완벽한)와 근거 없는 최상급·비교 숫자는 쓰지 마.
증거 단계에서 쓸 수 없는 주장(시연·전후 비교·성능)은 넣지 마.
구매 실패를 만드는 호환·미포함·납기 정보는 앞에 배치해줘.
자료에 없는 기능·수치·후기·인증·배송 보장은 만들지 마.
미확인 사항은 [공급처 확인 필요]로 표시하고 확인 요청 목록으로 남겨줘.
구성품과 사진 속 연출용 물건을 구분해줘. 개인정보는 넣지 마.
끝에 옵션 선택표·관리·고시/배송/반품 항목과 검수 목록을 정리해줘.
```

산출물은 바로 게시할 완성본으로 취급하지 않는다. 사실·권리·옵션 대조와 실제 화면 검수를 통과한 버전만 등록한다.

## 9. 무엇을 확인하면 작성이 끝난 것인가

- [ ] 첫 화면에서 무엇을 파는지와 사용 목적을 이해할 수 있다.
- [ ] 고객이 원하는 변화와 그것을 가능하게 하는 실제 특징이 연결돼 있다.
- [ ] 핵심 문장이 감정이 아닌 행동 변화로 쓰였고, 추상어·근거 없는 최상급·비교 숫자가 없다.
- [ ] 주장이 현재 증거 단계에서 쓸 수 있는 범위 안에 있다.
- [ ] 내게 맞는 옵션과 맞지 않는 환경을 구매 전에 구분할 수 있다.
- [ ] 포함/미포함 구성·필요한 도구·납기 조건이 숨겨져 있지 않다.
- [ ] 주장마다 해당 공급품의 근거가 있고, 미확인 내용을 사실처럼 쓰지 않았다.
- [ ] 제목·사진·옵션·본문·가격·배송 정보가 같은 상품과 조건을 가리킨다.
- [ ] 이미지 사용 범위와 필요한 표시·관리·반품·문의 정보를 확인했다.
- [ ] 모바일에서 선택표·치수·제한을 읽을 수 있고 반복·타상품 홍보가 판단을 방해하지 않는다.

실패한 항목은 수정하거나 자료를 추가한 뒤 다시 확인한다. 게시 후에는 잘못 고른 옵션·호환 문의·구성 오해가 반복되는 위치를 다음 개선 대상으로 기록한다.

## 10. 상세페이지가 실제 전환에 도움이 됐는지 어떻게 볼까

**리뷰 많은 상품을 분석했다고 우리 전략의 전환 효과가 입증된 것은 아니다.** 이번 조사는 판매 흔적이 강한 상품의 설명 방식에서 작성 가설을 얻은 것이다. 표본 선정·한계는 원본 조사 보고서(이 저장소에 포함하지 않음)에 있다.

공급 검증을 통과한 상품 하나에서 첫 화면의 차이 하나를 시험한다. 예를 들어 결과 장면 먼저 / 특징·호환 요약 먼저를 비교하고 하단 정보는 동일하게 둔다. 현관문 고무패킹 작업에서는 v1 첫 화면(조건 먼저)과 v2 첫 화면(원하는 동작 먼저)을 비교안으로 만들었다. 시험할 때는 아래 본문을 v2로 통일하고 첫 화면만 바꾼다. 가격·쿠폰·배송·재고·옵션·유입 메시지가 달라지면 함께 기록한다.

방문자 대비 주문을 비교할 때는 방문자 정의·기간·주문 집계 기준을 같게 맞춘다. 방문자당 이익, 취소·반품, 옵션·호환 문의도 함께 본다. 구매가 늘어도 잘못 산 주문과 비용이 늘면 개선으로 확정하지 않는다.

가능하면 무작위 분할을 사용한다. 기간을 번갈아 비교하면 요일·계절·광고·유입 변화가 섞이므로 탐색 결과로 기록한다. 필요한 방문량·기간·판정 기준은 실제 기초 데이터에서 정하고 임의 목표로 효과를 보장하지 않는다.

**다음 실행:** 공급 조건이 확인된 한 상품·한 옵션을 골라 8절 양식을 채운다. 4절에서 흐름과 답할 불만을 고르고, 6절 증거 단계를 정한 뒤 부족한 증거부터 확보한다. 그다음 구간별 초안을 쓰고, [디자인 가이드](design-guide.md)로 이미지 시안과 첫 화면 비교안을 만든다.
