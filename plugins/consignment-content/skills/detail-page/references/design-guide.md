# 상세페이지 디자인 가이드

> 용도: 전략서로 정한 내용을 **사고 싶게 보이는 상세 이미지**로 만들 때의 흐름·시각 규칙·제작 절차. 새 상품 상세페이지를 만들 때마다 이 문서로 시작함.
> 독자: 상세페이지를 기획·제작하는 작업자, 그리고 같은 작업을 맡는 AI(Claude·Codex).
> 자매 문서: [상세페이지 작성 전략서](strategy.md)(무엇을 말할지·증거 기준) · [제작 레슨런](lessons.md)(원칙·교훈, 시작 전 1장 확인) · [디자인 결정 기록](decision-log-template.md)(작업별 결정·과정·실수).
> 우선순위: **내용·문장·증거 규칙은 전략서가 우선.** 이 문서는 그 내용을 어떤 순서·모양으로 보여 줄지만 정함.
> 기준 결과물: [현관문 고무패킹 시안 v2](../assets/sample/현관문_시안예시/상세페이지.html) — 공급처 사진은 자리표시 이미지로 바꿨다. `render.py`로 섹션별 PNG를 뽑아 볼 수 있다.
> 시작 틀: [디자인 템플릿](template-guide.md) — 이 가이드의 뼈대·모양·도구를 복사해서 바로 쓰는 폴더.

## 1. 한눈에 보기

**정보를 다 담은 안내서는 팔리지 않음. 첫 화면에 원하는 변화, 중간에 구매 실패 데이터로 반전, 끝에 안심 장치를 둠. 근거 없는 효과 문구는 쓰지 않음.**

| 정할 것 | 기본값 | 자세히 |
|---|---|---|
| 흐름 | 11개 섹션 뼈대(첫 화면 → 자가진단 → 반전 → 확인 3개 → 사용법 → 안심 → 맞는 경우 → FAQ → 정보) | 2장 |
| 끌어당기는 장치 | 원하는 변화 문장 · 자가진단 · 실패 데이터 · 규칙 스티커 · 안심 장치 · 솔직한 필터 | 3장 |
| 모양 | 가운데 정렬 굵은 제목, 노란 형광펜, 사진 위 빨간 점선 주석, 배경 리듬 | 4장 |
| 사진 | 공급처 허용 사진을 잘라 씀. AI가 그린 제품 사진 금지 | 5장 |
| 만드는 법 | [템플릿](template-guide.md)을 복사해 HTML로 짜고 섹션마다 PNG(가로 860px)로 뽑음. 핵심 치수·옵션표는 글자로도 넣음 | 6장 |

그래서: 내용은 전략서로 정하고, 이 문서의 뼈대·장치·모양·절차를 그대로 따르면 같은 수준의 시안이 나옴.

## 2. 페이지 흐름은 어떻게 짜나

### 기본 뼈대 (11개 섹션)

한 섹션 = 고객 머릿속 질문 하나. 섹션 하나가 PNG 한 장이 됨.

| # | 섹션 | 고객 머릿속 질문 | 들어갈 것 | 현관문 예시 |
|---|---|---|---|---|
| 1 | 첫 화면 | 이게 뭐고 나한테 뭐가 좋아? | 원하는 변화 한 문장 + 가장 선명한 제품 사진 + 스펙 띠 + 구매를 막는 핵심 조건 한 줄 | “현관문 패킹, 직접 갈아 끼우세요” / 6.3m · 2.1m×3줄 · 18×14mm / 홈 있는 현관문 전용 |
| 2 | 자가진단 | 우리 집 얘기인가? | 고객의 **현재 상태** 체크리스트 3~4개 + 결론 한 줄 | 굳음·갈라짐·들뜸·눌림 → “하나라도 해당되면, 패킹을 갈 때” |
| 3 | 반전 | 그냥 사면 되나? | 이 상품군에서 사람들이 **후회한 이유** + 우리 조사 숫자(출처 각주) → “그래서 N가지만 확인하세요” 목록 | 후기 말풍선 4개 → 32/58건 → 01 홈 · 02 두께 · 03 길이 |
| 4~6 | 확인 01~03 | 우리 환경에 맞나? | 질문 하나당 한 섹션: 답 한 줄 + 증거 사진·그림 + 조건·제한 + 다음 행동 | 홈 유무 / 18mm 맞을까 / 2.1m×3줄로 충분한가 |
| 7 | 사용법 | 나도 할 수 있나? | 단계 사진 3장 + 구어체 제목 + 준비물 | “꾹! 꾹! 눌러 끼우면 끝” |
| 8 | 안심 장치 | 그래도 실패하면? | 실제로 운영할 수 있는 약속 하나 | 사진 보내면 맞는지 같이 봐 줌 |
| 9 | 맞는 경우·안 맞는 경우 | 최종 확인 | 두 칸 표 + 주의 한 줄 | 홈 있는 문 O / 홈 없는 문 X |
| 10 | 자주 묻는 질문 | 남은 궁금증 | 질문 4~6개 | 몇 개 오나, 남으면, 공구 |
| 11 | 정보·배송·반품 | 조건 확인 | 제품 정보 표 + 배송·반품 표 | 고시 정보 |

그래서: 4~6번(확인 섹션) 수는 전략서 결정 네 줄의 ‘구매 망설임’ 개수에 맞춰 1~4개로 늘리거나 줄임.

### 상품 유형별로 바꿔 끼우기

유형(A~E) 선택은 [전략서 2절](strategy.md#2-어떤-설득-순서를-선택할까)을 따름. 뼈대에서 바꾸는 곳만 정리함.

| 유형 | 2 자가진단 자리 | 3 반전 자리 | 4~6 확인 섹션 |
|---|---|---|---|
| C. 호환·선택 실패 방지 | 그대로 | 그대로(구매 실패 데이터) | 환경 확인 항목 |
| A. 문제·변화 | 불편한 상황 장면 | 왜 지금 방식으로는 안 되는지(구조) | 작동 장면·차이를 만드는 구조 |
| B. 성취·실패 방지 | 이루고 싶은 결과 | 실패하는 지점(난이도·납기) | 준비물·과정·포함 구성 |
| D. 익숙한 제품 재구매 | 빼고, 첫 화면에 제품명·규격·수량 | 빼기 | 옵션·구매 조건 |
| E. 첫 품질·취향 구매 | 사용 장면 | 고르다 실패하는 이유(핏·색) | 선택 가이드·실측·소재 |

그래서: D 유형은 짧게, C 유형은 확인 섹션을 가장 크게 다룸.

## 3. 근거 없이 끌어당기는 6가지 장치

경쟁 페이지 상당수는 “난방비 30% 절약”처럼 근거 없는 숫자로 끌어당김(경쟁 분석). 아래 장치는 공급처 자료 단계(전략서 [6절 1단계](strategy.md#6-어떤-주장에-어떤-증거가-필요한가))에서도 쓸 수 있음.

| 장치 | 쓰는 법 | 지킬 조건 |
|---|---|---|
| 원하는 변화 문장 | 고객이 하게 될 **동작**을 제목으로(“직접 갈아 끼우세요”) | 효과(외풍·소음)가 아니라 동작·결과. 공급처 원문에 있는 동작만 |
| 자가진단 | 고객의 지금 상태를 체크리스트로 | 제품 성능이 아니라 고객 쪽 상태만 적음 |
| 실패 데이터 반전 | 우리 조사 숫자를 크게(“32/58건”), 아래에 출처·분류 기준 각주 | 구매 전 확인으로 막을 수 있는 선택 실패 불만만. 애매한 항목은 빼고 보수적으로 셈. 경쟁사 이름·후기 원문은 싣지 않음. 우리 제품이 해결했다고 쓰지 않음([전략서 4절 예외](strategy.md#4-후보-상품의-고객-불만은-어떻게-쓸까)) |
| 규칙 스티커 | 실패를 막는 행동 하나를 스티커처럼(“자르기 전에, 한 줄 먼저!”) | 실제 불만에서 나온 규칙이어야 함 |
| 안심 장치 | 상담·교환 등 위험을 덜어 주는 약속 | **실제로 운영할 수 있을 때만.** 넣기 전 운영 여부·응답 시간 결정([전략서 6절](strategy.md#6-어떤-주장에-어떤-증거가-필요한가)) |
| 솔직한 필터 | 안 맞는 경우를 표로 먼저 말함 | 기준값이 미확인이면 확인 필요 표시 |

쓰지 않는 것:
- 효과 수치·단정(“30% 절약”, “완벽 차단”, “소음 차단”) — 시험 자료가 없으면 금지
- 측정 없는 타사 비교(“타사보다 밀착 면적이 많다”), 근거 없는 희소성(“품절 임박”)
- 경쟁사 후기 캡처·판매자명, 경쟁사 순위·판매량을 우리 것처럼 보이게 하는 표현
- AI로 그린 제품 사진, 생성한 고객 후기·반응

그래서: “사고 싶게”의 재료는 효과 약속이 아니라 **고객 상황 공감 + 실패 회피 + 안심**에서 가져옴.

## 4. 어떤 모양으로 만드나

### 4-1. 색 — 강조색 하나, 주석색 하나로 고정

| 이름 | 값 | 쓰는 곳 | 쓰지 않는 곳 |
|---|---|---|---|
| 먹색 | `#141414` | 제목, 본문, 굵은 선, 어두운 띠 | — |
| 보조 글자 | `#3B3B3B` / `#727272` | 설명 문장 / 작은 안내 | 제목 |
| 바탕 | `#FFFFFF` · 연회색 `#F2F1ED` · 어두운 `#171717` | 섹션 배경(4-3 리듬) | — |
| **노랑(강조)** | `#FFE04A` | 형광펜, 스티커, 어두운 배경의 강조 글자, 안심 섹션 배경 | 흰 배경 위 노란 글자(안 보임) |
| **빨강(주석·경고)** | `#EB3B26` | 사진 위 점선 원·라벨, 경고 문장, X 표시 | 일반 강조 |
| 선 | `#DCDAD4` | 표 안쪽 선 | — |
| 파랑(검수용) | `#1D6FE8` / `#EAF2FF` | `확인 필요` 표시만 | 디자인 요소 |

그래서: 상품마다 노랑·빨강을 바꿔도 되지만 한 페이지 안에서는 강조색 1개 + 주석색 1개만 씀. 색이 일관되면 브랜드처럼 보임.

### 4-2. 글꼴·크기 — 휴대폰에서는 약 0.45배로 보임

스마트스토어 상세 이미지 권장 폭은 가로 860px([스마트스토어 고객센터](https://m-help-sell.smartstore.naver.com/faq/list.help?rootCategoryId=525&faqId=3923&relatedHelp=true)). 휴대폰(화면 폭 390px)에서는 약 0.45배로 줄어 보임.

| 역할 | 글꼴 | 크기(860px 기준) | 휴대폰에서 |
|---|---|---|---|
| 첫 화면 제목 | G마켓 산스 Bold | 76~80px | 약 35px |
| 섹션 제목 | G마켓 산스 Bold | 58~62px | 약 27px |
| 큰 숫자 | G마켓 산스 Bold | 140~150px | 약 66px |
| 소제목·결론 한 줄 | G마켓 산스 Bold | 42~50px | 약 20px |
| 본문·설명 | 프리텐다드 | 28~32px | 약 13~14px |
| 표·목록·주의 문장 | 프리텐다드 | 24~27px | 약 11~12px |
| 출처·그림 안내 | 프리텐다드 | **22px 이상** | 약 10px |

- 제목·숫자는 G마켓 산스(굵고 각진 한국 상업용 서체), 읽는 글은 프리텐다드.
- 22px 미만 글자는 휴대폰에서 거의 안 읽힘. 템플릿은 22px를 적용함. 현관문 v2의 출처·그림 안내는 20px라 다음 수정 때 22px로 올려야 함.
- 숫자와 단위가 줄바꿈으로 갈리지 않게 `18&nbsp;×&nbsp;14mm`처럼 붙임.

### 4-3. 배경 리듬 — 같은 배경을 연달아 두지 않음

| 배경 | 쓰는 섹션 | 이유 |
|---|---|---|
| 흰색 | 첫 화면, 확인 섹션, 맞는 경우, 정보 | 사진·표를 깨끗하게 |
| 연회색 | 자가진단, 확인 섹션(교대), FAQ | 흰색과 교대해 구간 구분 |
| 어두운 색 | 반전, 사용법 | 분위기를 바꾸는 지점. 사진이 또렷해짐 |
| 노랑 | 안심 장치 1곳만 | 한 번만 써야 눈에 띔 |

현관문 v2 순서: 흰 → 연회 → 어두움 → 흰 → 연회 → 흰 → 어두움 → 노랑 → 흰 → 연회 → 흰.

### 4-4. 구성 요소

| 요소 | 언제 | 규칙 |
|---|---|---|
| 두 줄 제목 | 모든 섹션 | 가운데 정렬. 둘째 줄에 핵심, 핵심 단어 하나만 형광펜 또는 색 |
| 형광펜 | 핵심 구절 1곳 | 글자 아래 절반을 노랑으로. **어두운 배경에서는 노란 상자 전체 + 검은 글자**(절반만 칠하면 위쪽 글자가 안 보임) |
| 확인 배지 | 확인 섹션 머리 | 검은 상자에 노란 “CHECK 01”, 양옆 점선 |
| 사진 주석 | 증거 사진 | 빨간 점선 원 + 지시선 + 빨간 라벨(“이 홈에 끼워요”) |
| 말풍선 | 반전 섹션 | 후기 내용을 짧게 줄인 문장. 좌우 번갈아. “후기를 줄인 문장” 안내 필수 |
| 큰 숫자 | 반전 섹션 | 숫자 하나 + 해석 한 줄 + 출처 각주 |
| 스티커 | 규칙 하나 | 노란 상자, 2~3도 기울임, 흐림 없는 검은 그림자 |
| O/X 그림 | 되는 경우·안 되는 경우 | 굵은 테두리 두 칸. 그림 아래 “이해를 돕기 위한 그림” 안내 |
| 단계 사진 | 사용법 | STEP 01~03 큰 숫자 + 같은 비율로 자른 사진 + 두 줄 설명 |
| 스펙 띠 | 첫 화면 | 검은 띠에 노란 숫자 3칸 |
| 계산 띠 | 길이·수량 | 검은 띠에 노란 공식(“세로 × 2 + 가로 ≤ 6.3m”) |
| 맞는/안 맞는 표 | 마지막 확인 | 두 칸, 굵은 테두리, O는 검정·X는 빨강 |
| 확인 필요 표시 | 미확인 값 | 파란 점선 상자. 디자인과 구분되게 파랑만 사용 |

### 4-5. “AI가 만든 것 같은” 모양을 피하는 법

| AI 같아 보이는 모양(v1) | 바꾼 모양(v2) |
|---|---|
| 둥근 카드가 반복되는 앱 화면 같은 배치 | 굵은 선 표·풀폭 띠·사진 중심 |
| 알약 모양 작은 칩, 숫자 동그라미 | 검은 상자 배지, 큰 숫자 |
| 왼쪽 정렬 문서형, 모든 정보가 같은 무게 | 가운데 정렬, 제목·숫자는 크게, 설명은 작게 |
| 차분한 단색, 흐린 그림자 | 강조색 노랑 하나, 흐림 없는 그림자 |
| 사진이 작고 설명이 많음 | 사진 크게 + 사진 위 주석 |
| 안내문 말투 | 구어체 한 줄(“꾹! 꾹! 눌러 끼우면 끝”) |
| 섹션 전체를 AI 이미지로 생성 | 실제 사진 + 직접 그린 단순한 그림 |

그래서: 한국 상세페이지에서 흔히 쓰는 표현(굵은 제목·형광펜·주석·배경 교대)을 쓰고, 사진은 실물만 씀.

## 5. 사진·그림 규칙

| 항목 | 규칙 |
|---|---|
| 출처 | 공급처가 사용을 허용한 상세 이미지 또는 직접 찍은 사진만. 사진 아래 “공급처 제공” 표시 |
| 해상도 | 대표 썸네일보다 상세 이미지 원본이 큰 경우가 많음. **가장 큰 원본에서 자름**(현관문: 썸네일 500px, 상세 원본 800px) |
| 자를 때 뺄 것 | 공급처 사진 속 효과 문구 띠, 라이터 시연처럼 근거 없는 성능 장면 |
| 작은 사진 | 2배로 키우고 선명하게(아래 코드). 화면에는 원본 폭의 약 1.7배까지만 크게 보여 줌(현관문 v2에서 256px 사진을 440px로 썼을 때 볼 만했음. 그 이상은 시험 안 함) |
| 주석 위치 | 사진에 격자를 그려 좌표를 읽은 뒤 표시. 눈대중 금지 |
| 그림 | 단면·배치·측정 위치는 단순한 도형으로 직접 그림. 실물 사진처럼 꾸미지 않음 |
| AI 이미지 | 제품·사용 장면·후기 이미지를 생성하지 않음(전략서 [6절](strategy.md#6-어떤-주장에-어떤-증거가-필요한가)) |

그래서: 사진이 부족하면 생성하지 말고 그 섹션을 줄이거나 샘플 촬영 목록에 올림.

## 6. 어떻게 만드나 — HTML에서 PNG까지

### 시작 전 확인

- [ ] 전략서 기준 초안(md)에 결정 네 줄·구간·근거가 채워져 있음 (`assets/template/초안_양식.md` 참고)
- [ ] 공급처 이미지 사용 허용을 확인함
- [ ] 이 컴퓨터에 Python3, Playwright(파이썬으로 브라우저를 열어 화면을 저장하는 도구), Pillow(이미지 자르기 도구), Google Chrome이 있음. 확인: `python3 -c "import playwright, PIL"` 오류 없음

### 절차

전략서 진행 절차의 [6단계 ‘이미지 시안’](strategy.md#7-기획부터-검수까지-어떻게-진행할까)을 자세히 푼 것.

| 단계 | 할 일 | 성공 신호 | 막히면 |
|---|---|---|---|
| 1. 템플릿 복사 | `scripts/new_product.py detail <상품명>`이 [디자인 템플릿](template-guide.md)을 `상품별초안/<상품명>/상세페이지_디자인/`으로 복사하고 `원본이미지/`·`이미지/`를 만듦(손으로 복사해도 같음) | 파일 4개(`상세페이지.html`·`style.css`·`render.py`·`README.md`) + `도구/` + 사진 폴더 2개 | — |
| 2. 원본 사진 받기 | 공급처 상세 페이지에서 큰 이미지 주소를 찾아 `원본이미지/`에 저장 | 파일 크기·해상도가 정상(`file` 명령으로 JPEG·크기 확인) | 받기가 실패하면 브라우저 정보·이전 페이지 주소를 붙여 다시 받음(아래 코드) |
| 3. 사진 자르기 | `split`으로 950px 조각을 만들어 직접 보고, 쓸 사진을 `crop`으로 `이미지/`에 저장한 뒤 `sheet`로 모아 확인 | 모아 본 사진에 글씨·효과 띠가 안 섞임 | 좌표가 어긋나면 조각 파일명의 시작 y좌표를 더했는지 확인 |
| 4. HTML 쓰기 | 섹션마다 `<section class="slice" id="s01-이름">`. 문구는 초안에서, 모양은 4장 규칙대로 | 브라우저로 열었을 때 깨진 사진 없음 | 사진이 안 뜨면 `이미지/` 상대 경로 확인 |
| 5. PNG 뽑기 | `python3 "<render.py 절대경로>"` 실행 | 섹션별 `가로 860 x 높이`가 한 줄씩 출력되고 `출력/`에 PNG 생성 | 아무 출력 없이 실패하면 `cd` 없이 절대경로로 실행 |
| 6. 눈으로 검수 | 섹션 PNG를 전부 열어 7장 체크리스트로 확인 → 고치고 5번 반복 | 체크리스트 전부 통과 | — |
| 7. 금지어 검사 | `도구/check_copy.py`로 효과 문구·남은 대괄호·확인 필요 표시 검사 | 효과 표현 0건(확인 필요 표시 안은 검사에서 빠짐) | 걸린 문구는 지우거나 근거 확보 |
| 8. 숫자 대조 | 페이지의 모든 숫자를 근거 파일과 하나씩 대조 | 숫자마다 근거 파일 위치를 댈 수 있음 | 애매하면 보수적으로 줄이고 각주에 기준 공개 |
| 9. 글자 정보 준비 | 핵심 치수·옵션표·제한·고시 정보를 스마트스토어 편집기에 넣을 글자·표로도 정리. 이미지 속 글자로만 두지 않음([전략서 3절](strategy.md#3-첫-화면과-각-구간은-어떻게-작성할까)) | 이미지를 빼고 글자만 읽어도 맞는 조건·구성을 알 수 있음 | — |
| 10. 기록·보관 | 크게 바꾸기 전 버전은 `이전버전/v1/`로 옮김. 초안 md에 흐름·추가 문구·근거 표를 남기고, [결정 기록](decision-log-template.md)에 결정·과정·실수를 추가. 다음에도 적용될 교훈은 [레슨런](lessons.md)으로 옮김 | 결정 기록에 이번 작업 항목이 있음 | — |

### 자주 쓰는 명령

도구는 [디자인 템플릿](template-guide.md)의 `도구/` 폴더에 있음. 자세한 사용법은 템플릿 README 3장.

| 단계 | 명령 |
|---|---|
| 2. 원본 사진 받기(첫 시도가 실패했을 때) | `curl -sSL -A 'Mozilla/5.0' -e '<공급처 상품 페이지 주소>' -o "<원본이미지 폴더>/원본.jpg" '<이미지 주소>'` |
| 3. 나눠 보기 · 좌표 격자 | `python3 "<D>/도구/image_tools.py" split "<원본>"` · `… grid "<조각>" --y0 <조각 시작 y>` |
| 3. 자르기 · 모아 보기 · 키우기 | `… crop "<원본>" x1 y1 x2 y2 "<저장 경로>"` · `… sheet "<저장 경로>" <사진들>` · `… upscale "<사진>"` |
| 5. PNG 뽑기 | `python3 "<D>/render.py"` |
| 7. 금지어 검사 | `python3 "<D>/도구/check_copy.py" "<D>/상세페이지.html" --extra 단어,단어` |

`<D>`는 상품의 `상세페이지_디자인` 폴더 절대경로. 상품군에 따라 금지어를 `--extra`로 더함(예: 식품은 질병 이름, 화장품은 “치료·재생”).

## 7. 다 됐는지 확인 — 디자인 검수

내용 검수는 [전략서 9절](strategy.md#9-무엇을-확인하면-작성이-끝난-것인가)을 먼저 통과시킴. 그다음 아래를 확인함.

- [ ] 첫 화면만 보고 무엇을 파는지·누구용인지·핵심 조건을 알 수 있음
- [ ] 섹션 하나에 질문 하나. 섹션 PNG 높이가 너무 길지 않음(현관문 v2: 945~2,371px)
- [ ] 같은 배경이 연달아 나오지 않음. 노랑 배경은 한 곳
- [ ] 형광펜·색 강조는 섹션당 1~2곳. 어두운 배경 강조는 노란 상자 전체
- [ ] 줄바꿈으로 숫자·단위가 갈리거나 한 글자만 다음 줄로 넘어간 곳 없음
- [ ] 나란히 놓은 카드·사진의 높이가 같음
- [ ] 사진 주석이 가리키는 위치가 정확함. 사진마다 출처 표시
- [ ] 그림에는 “이해를 돕기 위한 그림” 안내
- [ ] 출처·각주 22px 이상, 설명 문장 24px 이상
- [ ] 금지어 검사 통과, 숫자 대조 완료
- [ ] 미확인 값은 모두 파란 확인 필요 표시. 이 표시가 남아 있으면 등록하지 않음
- [ ] 핵심 치수·옵션표·제한을 이미지 밖 글자·표로도 준비함
- [ ] 휴대폰 실제 화면(또는 폭 390px 축소)에서 읽어 봄

## 부록. 파일 구조와 HTML 이름표

```text
상품별초안/<상품명>/
├── 상세페이지_초안.md          ← 무엇을 말할지(전략서 기준)
├── 근거/                       ← 공급처 원문·고객 불만·경쟁 분석
└── 상세페이지_디자인/           ← 디자인_템플릿/ 을 복사해 시작
    ├── 상세페이지.html         ← 시안(섹션 = <section class="slice">)
    ├── style.css               ← 공통 모양(색 값만 상품별로 조정)
    ├── render.py               ← 섹션별 PNG + 전체 미리보기 생성
    ├── 도구/                   ← image_tools.py(사진) · check_copy.py(문구 검사)
    ├── 원본이미지/             ← 공급처에서 받은 원본(나눈 조각은 원본_조각/)
    ├── 이미지/                 ← 잘라 낸 사진
    ├── 출력/                   ← sNN-이름.png, 00_전체_미리보기.png
    └── 이전버전/vN/            ← 크게 바꾸기 전 버전
```

| 구성 요소 | HTML 이름표(class) |
|---|---|
| 섹션(=PNG 한 장) | `slice` + 배경 `bg-panel` · `bg-dark` · `bg-yellow` |
| 제목 | `h1` · `h2` · `h3`, 작은 머리글 `kicker` |
| 형광펜 · 색 강조 | `hl` · `red` · `y` |
| 확인 배지 | `badge` |
| 사진 주석 | `anno`(사진 묶음) + `svg.over`(점선 원) + `tag`(라벨) |
| 말풍선 · 큰 숫자 | `chat` · `bubble` / `stat` |
| 스티커 | `sticker` |
| O/X 그림 · 재는 위치 그림 | `duo` · `dg` |
| 그림 + 설명 두 단 | `split` |
| 단계 사진 | `steps` |
| 스펙 띠 · 계산 띠 | `specbar` · `formula` |
| 맞는/안 맞는 표 · FAQ · 정보 표 | `fit` · `faq` · `table.info` |
| 확인 필요 표시 · 사진 자리 표시 | `todo` · `ph-box` |

전체 목록과 값은 템플릿 style.css. 현관문 v2는 템플릿보다 먼저 만들어 HTML 안에 스타일이 들어 있고, `split` 대신 `door`라는 이름을 씀.
